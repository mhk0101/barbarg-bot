رفع واقعی دکمه‌ی خروج — صفحه ری‌لود می‌شد ولی خارج نمی‌شدی
════════════════════════════════════════════════════════════

نشانه‌ای که گفتی
  «روی خروج زدم، فقط صفحه یک‌بار لود میشه و همونجا میمونه،
   برمیگرده ولی خارج نمیشه»

این دقیقا یعنی: کلیک کار کرد (رفع قبلی درست بود)، ولی
سشن پاک نشد.


علت واقعی — دو سیستم احراز هویت موازی
─────────────────────────────────────────────────────
پروژه دو سیستم لاگین دارد که هیچ ارتباطی با هم ندارند:

 ┌────────────┬──────────────────┬─────────────────────┐
 │            │ سیستم A (واقعی)  │ سیستم B (تزئینی)    │
 ├────────────┼──────────────────┼─────────────────────┤
 │ ورود       │ /api/auth/login  │ NextAuth            │
 │ کوکی       │ access_token     │ authjs.session-token│
 │            │ + refresh_token  │                     │
 │ نگهبان پنل │ (panel)/layout   │ هیچ                 │
 │ کارکرد     │ ورود واقعی       │ فقط نام/ایمیل منو   │
 └────────────┴──────────────────┴─────────────────────┘

دکمه‌ی خروج فقط signOut() صدا می‌زد ← یعنی فقط کوکی
NextAuth (سیستم تزئینی) را پاک می‌کرد.

کوکی access_token که نگهبان واقعی پنل است، دست‌نخورده
می‌ماند. پس:
   صفحه ری‌لود می‌شود
   → (panel)/layout.tsx کوکی را می‌بیند
   → می‌گوید «این کاربر معتبر است»
   → دوباره پنل را نشان می‌دهد

نکته‌ی کلیدی: access_token با httpOnly:true ست شده،
یعنی جاوااسکریپت اصلا نمی‌تواند پاکش کند. حتما باید
سرور پاکش کند.


چیزی که خنده‌دار بود
─────────────────────────────────────────────────────
متد DELETE در /api/auth/login از قبل وجود داشت و
کاملا درست هم بود — حتی سشن را در دیتابیس می‌بست.
فقط هیچ‌کس هرگز صدایش نمی‌زد.


چه چیزی تغییر کرد
─────────────────────────────────────────────────────
۱) src/components/layout/Header.tsx
   handleSignOut حالا سه کار می‌کند:
     الف) fetch('/api/auth/login', { method: 'DELETE' })
          ← سرور access_token و refresh_token را پاک می‌کند
     ب) signOut({ redirect: false })
          ← سشن NextAuth هم بسته می‌شود
     ج) window.location.href = '/login'
          ← ناوبری کامل، نه router.push، تا کش سمت سرور
            هم تازه شود

   اگر هر کدام از دو مرحله‌ی اول خطا بدهد، باز هم مرحله‌ی
   سوم اجرا می‌شود؛ کاربر هیچ‌وقت گیر نمی‌کند.

۲) src/app/api/auth/login/route.ts
   تابع clearAuthCookies() اضافه شد.

   چرا لازم بود: کوکی با path:'/' ست شده بود ولی
   delete بدون path صدا زده می‌شد. در بعضی نسخه‌های Next
   این باعث می‌شود کوکی اصلا پاک نشود.
   حالا هم delete با path و هم مقدار خالی با
   maxAge:0 و expires:1970 ست می‌شود (کمربند و ساسپاند).


هدرهایی که سرور خواهد فرستاد
─────────────────────────────────────────────────────
 Set-Cookie: access_token=; Path=/; Max-Age=0;
             Expires=Thu, 01 Jan 1970...; HttpOnly; SameSite=lax
 Set-Cookie: refresh_token=; Path=/; Max-Age=0; ...

سپس (panel)/layout.tsx:
   token = undefined  →  redirect('/login')  ✔


نصب
  ۱) روی ریشه‌ی پروژه اکسترکت کن (Replace)
  ۲) Ctrl+F5
  ۳) خروج را بزن — باید به صفحه‌ی ورود برود و بماند

  اگر بعد از خروج آدرس /panel را دستی وارد کنی، باید
  دوباره به /login پرت شوی. این تست واقعی است.


نکته‌ی معماری (برای بعد)
─────────────────────────────────────────────────────
داشتن دو سیستم احراز هویت موازی سردرگمی و باگ می‌سازد.
پیشنهاد می‌کنم یکی‌شان حذف شود — ولی گفتی پروژه‌ی اصلی
را بدون اجازه دست نزنم، پس فعلا هر دو را هماهنگ کردم.
هر وقت گفتی، تمیزش می‌کنم.
