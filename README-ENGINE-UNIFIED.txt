مشکل چه بود؟
  تب «اتوماسیون» و فایل test-step1.js دو کد کاملا جدا بودند:
     کپچا : classifyTemplate() داخل تستر  ⟷  CaptchaSolver.ts در پنل
     لاگین: حلقه‌ی داخل main()            ⟷  LoginFlow.ts
     فرم  : fillPersonStep و ...          ⟷  WaybillFlow.ts
  برای همین تستر کار می‌کرد ولی پنل نه.

حالا چه شد؟
  فایل جدید:
      src/automation/engine/step1-engine.js
  این «کپی بی‌کم‌وکاست» توابع test-step1.js است (خط ۱۱۱ تا ۱۳۷۵ عینا).
  هم ورکر پنل و هم تستر همین یک فایل را صدا می‌زنند ⇒ رفتار همیشه یکسان.

فایل‌های این زیپ
  src/automation/engine/step1-engine.js   ← جدید (موتور مشترک)
  worker/processor.ts                     ← بازنویسی: فقط موتور را صدا می‌زند
  test-step1.js                           ← پوسته‌ی نازک روی همان موتور

دیگر استفاده نمی‌شوند (پاک نکردم، دست‌نخورده ماندند):
  CaptchaSolver.ts / LoginFlow.ts / WaybillFlow.ts

نصب
  1) زیپ را روی ریشه‌ی پروژه اکسترکت کن (Replace)
  2) پنجره‌ی Worker را ببند و دوباره باز کن  (start.bat)
  3) پنل → پروفایل‌ها → مطمئن شو پروفایل کامل است
  4) پنل → اتوماسیون → مرکز کنترل → پروفایل را انتخاب کن، تعداد ۱ → افزودن به صف

تنظیمات اختیاری در .env
  BARBARG_SUBMIT=false     ← حالت آزمایشی: تا گام ۹ می‌رود ولی ثبت نهایی نمی‌زند
  BARBARG_SUBMIT=true      ← ثبت واقعی (پیش‌فرض)
  BARBARG_HEADLESS=true    ← مرورگر مخفی (پیش‌فرض: دیده می‌شود، مثل تستر)

توصیه‌ی من: بار اول BARBARG_SUBMIT=false بگذار.

تفاوت داده
  تستر بدون سوییچ  → داده‌ی نمونه‌ی ثابت
  تستر با --profile → داده‌ی پروفایل دیتابیس
  پنل              → همیشه داده‌ی پروفایلی که خودت وارد کردی (هیچ داده‌ی ثابتی نیست)

اگر فیلد اجباری خالی باشد، قبل از باز شدن مرورگر در لاگ می‌نویسد
دقیقا کدام فیلد خالی است.
